term	what it means in this appendix	the Lean's word
public files	Three byte strings, parameters of the whole argument system: the parameter file, the layout file and the scale file.	`VerifierAndGoals.PublicFiles` (pol, lay, KL)
IOP	A public-coin interactive oracle proof with a fixed list of rounds, an instance, and external oracle strings that are fixed before the first message. The queried positions are functions of the instance and the challenges (in the prover's oracle messages also of the messages' plain parts). By its type, the decision takes the whole transcript; that it depends on the oracles at the queried positions alone is a separate property, `InteractiveOracleProof.IsLocal`.	`Iop.InteractiveOracleProof`
configuration	What the three IOPs share: index and instance types, two relations `Ryes` and `Rno` (no field relates them; in this protocol they are the same), the encoding of an index as a word of n symbols, seeds and answers, and the index decoder.	`Hiop.ConfigurationWithOutOfDomainSample`; here `DecR.configurationOfStoredTable A R`
pads	(1) Of the configuration: a value of the type `Pad` that `hold` places in the message beside the index. (2) Of a tenant: the entries reserved for its answers (see "seed; answer").	`ConfigurationWithOutOfDomainSample.Pad`, `hold`; `Msg.pad`
committed table	The encoded index as an external oracle string: 2^a symbols, which the verifier queries by position; a is the table depth. What is encoded is a message of field elements, indexed by row and entry.	stored table; encoded index; `oneExternalString (2 ^ a) SgX`, `ConfigurationWithOutOfDomainSample.E0`
out-of-domain sample	(1) Of a committed table: seeds, each a point and a nonzero factor, and the answers of every row to each seed. It is part of the instance of each of the three IOPs. In this protocol: one seed, a point of 29 coordinates and a nonzero factor, and one answer for each of the table's 2^v rows. (2) Of a tenant whose flag `sampled` is set: the verifier samples seeds in the round that sends it, and the prover's next message contains the answers.	(1) record; `ConfigurationWithOutOfDomainSample.Rec` = Seed × Ans; `RecFull` (2) `SymbolComponent.sampled`
the offline IOP	Instance: one out-of-domain sample. Oracle: one committed table. Three chains.	`Files.key`; key file
the link IOP	Instance: two out-of-domain samples. Oracles: two committed tables. One chain. In the Lean: the entry file.	`Files.entry`; entry file; `HolographicProtocol.link`
the online IOP	A request's proof. Instance: a request and one out-of-domain sample. Oracle: one committed table. Three chains.	`Files.proof`; proof file
request	The instance type of the online IOP. It is not printed in this appendix.	`XF` := `Flat.Req`
full parameter size	The library has two fixed sets of size parameters. This protocol uses the larger one.	`frS`, `frP`, `recordLines` against `srS`, `srP`, `smallRecordLines`
statement	(1) A top-level statement: one of the theorems' statements on the argument system, in the main part of this document. (2) A chain's statement, in the byte format: a list of items; a committed table's root is held by one of them, whose number is the table's `item`. (3) The trivial statement: what an interactive oracle reduction reduces to when nothing is left to prove.	(2) `statement`, `itemRoot` (3) `Unit`, `extNone`
