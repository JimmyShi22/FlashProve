term	what it means in this appendix	the Lean's word
written IOP	An IOP written in the format that this appendix prints: a value of `FileDescription` (three chains) or `OneChainFileDescription` (one chain).	description
chain	A consecutive part of an IOP that has a verifier state and a view of its own. The three chains are the fields `first`, `shared`, `second`, here called first, second, third (chains 1, 2, 3). Addresses and `before` number them 1 to 3; tree sources and `BookPlan` number them 0 to 2.	`Chain`
segment	A part of a chain in which sub-protocols state claims and one sub-protocol, `batch`, is handed the function that gathers them.	`Link`
sub-protocol	The unit in which an IOP is written: some rounds, their oracle messages and queries, and a step of the verifier's decision.	`Block`
kind	A family of sub-protocols: fifteen, each with a plain name; in Lean their labels are `K1` to `K15`. (In Lean, `Fmt.Kind` is another thing, here called the challenge kind: what a round's challenge consists of, read off the round's name by `Fmt.kindOf`.)	`KindName`, `Kind`; `Fmt.Kind`
address	The location of a sub-protocol: chain, segment, number, kind. ("Position" is reserved for a queried position.)	`Place`
verifier state	The value that the verifier's decision carries from one sub-protocol of a chain to the next.	S; "the carried record"
claim	A value of the type Cl that a sub-protocol states from the verifier state, to be gathered for its segment's sub-protocol `batch`. What a claim asserts depends on the written IOP.	Cl; `Block.claims`
schedule; declared round	A chain's schedule lists for each round a name and eleven numbers. A declared round is such an entry together with the committed tables that the round queries, each at its share of the sampled positions, and the Merkle trees that it opens.	plan, `Fmt.Entry`; `Fmt.DeclaredRound`
matrix entries	Values in {−1, 0, 1} that a round's challenge may hold beside field elements and positions.	`Drawn.trits`, `Entry.trits`; challenge kind `entries`
oracle message; tenant	An oracle message is the data under one Merkle root: 2^logLength symbols of a fixed number of words. Its tenants are the data that share its symbols, each with a fixed number of main and mask words in every symbol. A tenant's `groups` are numbers; the definitions printed here only compare these lists, and only add up the counts of main and mask words.	`Oracle`; `SymbolComponent`
tree, root, to open	The schedule counts each oracle message as one Merkle root in its round's message; the message's tree is that commitment in the compiled protocol. A committed table has a tree too. "A round opens a tree" means: the verifier queries that oracle at the positions sampled in the round.	`Entry.roots`, `DeclaredRound.opens`, `Shape`
shape; column; key; width	A shape is what a round declares of a tree that it opens: depth a, width W, whether it is a committed table's, the tree number. A column is the symbol at one queried position: a key, which names the oracle, the position, and W 64-bit words, each a base-field element.	`Fmt.Shape`; `OpenedColumn`
round's values; view	A round's values are the items of the prover's message, Merkle roots left out, and the sampled challenge. A view is what the decision sees of one chain: its rounds' values and the list of opened columns.	`Fmt.RoundView`; `Fmt.View`
public check; file check	A public check is a Boolean that depends on public data alone (the written IOP, the public files, what the planner returns), not on the instance or a view. The file check is the Boolean `fileOk` that a written IOP has as a field.	"test on the plan"; `planOk`; `fileOk`
