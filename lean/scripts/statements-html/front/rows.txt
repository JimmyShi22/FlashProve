@ structure ArgumentSystem where
a structure of four types and six functions
# margin: Types
@ /-- What a commitment commits to: the weights of
what a commitment commits to: the weights of one model
# margin: 
@ /-- What proofs may reveal of the weights (exact
the public parameters: a part of the weights that the simulator is given at its start ([§6.2](#sec-zk-exp)), and the function that computes it; anything else that a simulator is given about the weights is a parameter of the statement ([§6.3](#sec-zk))
# margin:

# margin: 
@ /-- A proof. -/
a proof
# margin: Model
@ /-- The model: the next token after the given to
the model: a function mapping weights and a list of tokens to the next token, or to nothing if the model has no value on these tokens. It neither queries the hash function nor samples randomness.
# margin: Committer
@ /-- The honest committer, first step: it samples
the honest committer: it samples its randomness, computes the commitment to the weights under it, publishes the commitment and keeps the randomness
# margin: Prover
@ /-- The honest prover: from the weights, the com
the honest prover: computes a proof from the weights, the committer's randomness, a prompt and output tokens. It may sample randomness and query the hash function.
# margin: Verifier
@ /-- The verifier: from a commitment, a prompt, o
the verifier: maps a commitment, a prompt, output tokens and a proof to a decision. It is deterministic (`DeterministicAlgorithm`) and accesses the hash function only through queries.

=== VerifiableInference.Compilation.finalCompletenessError
@ abbrev finalCompletenessError
`finalCompletenessError` is the constant `VerifierAndGoals.completenessErrorBound`, which is (1/2)^40 = 2^-40. In the theorem `completeOnCanServe` it bounds the probability that the verifier rejects the honest prover's proof. A nonzero bound allows for the honest prover's searches for a proof-of-work nonce, which stop after a bounded number of tries.
=== VerifiableInference.Compilation.finalSoundnessError
@ abbrev finalSoundnessError
The bound in the soundness theorem, as a function of the number of hash queries.
- `finalSoundnessError q` is `VerifierAndGoals.soundnessErrorInQueries q 1`
- with T = q + 1 + 2^23 it is 16 · T / 2^128 + (T + 2)^2 / 2^256, which is about q / 2^124 + 2^-101
- q bounds the hash queries of the committer and the prover together
- 1 is the allowance for the parser's queries
- 2^23 (`VerifierAndGoals.verifierQueryAllowance`) is the allowance for the verifier's own queries
=== VerifiableInference.Compilation.finalBindingError
@ abbrev finalBindingError
`finalBindingError q` is `VerifierAndGoals.levelError q`, the larger of `VerifierAndGoals.soundnessErrorInQueries q (2^23)` and `VerifierAndGoals.bindingErrorInQueries q`. The first is 16 · T / 2^128 + (T + 2)^2 / 2^256 at T = q + 2^23 + 2^23; the second is 16 · (q + 2^23) / 2^128 + (q + 2^48 + 2^23 + 2)^2 / 2^256, where 2^48 is `VerifierAndGoals.honestBudget`. The value is about q / 2^124 + 2^-100.
=== VerifiableInference.Compilation.honestQueryBudget
@ abbrev honestQueryBudget
`honestQueryBudget` is the constant `VerifierAndGoals.honestBudget`, which is 2^48. The theorem `repliesFit` uses it through `WithinBudget` ([§6.1](#sec-completeness)): one run each of the honest sampler of commitment randomness, the honest committer and the honest prover may together make at most this many queries to the hash function.
=== VerifiableInference.Compilation.finalVerifierQueries
@ abbrev finalVerifierQueries
`finalVerifierQueries` is the constant `VerifierAndGoals.queryBudget`, which is 2^64. The theorems on zero knowledge bound the statistical distance only for verifiers that make at most this many hash queries.
=== VerifiableInference.Compilation.finalReplyCount
@ abbrev finalReplyCount
`finalReplyCount` is the number 688127. The theorems on zero knowledge give their bound for up to this many replies under one commitment, and the theorem `repliesFit` shows that it is at most `onlineRunsPerCopy`. === VerifiableInference.Compilation.honestProversAndSettings
@ noncomputable def honestProversAndSettings
The honest provers and settings of the six theorems: a single closed term that gives, for every choice of public files and settings:
- the three honest IOP provers
- the honest committer's and prover's settings: what they choose in addition to the provers, including the public prefixes of their salts, how long a search for a nonce may run, and a fall-back instance
It contains no committer: `compile` constructs the honest committer.
It is a definition, not a program: it obtains the model's trace by a non-constructive choice.
The verifier reads none of it.
=== VerifiableInference.Compilation.finalZeroKnowledgeError
@ def finalZeroKnowledgeError
2^-154, the bound in the zero-knowledge theorems `zeroKnowledgeOnCanServe` and `zeroKnowledgeAtEveryRequest`. It is a statistical distance, for up to 688,127 replies and 2^64 hash queries; it is not a security level.

=== VerifierAndGoals.honestBudget
@ def honestBudget
The maximum number of hash queries that one run each of the honest sampler, committer and prover may make together. The value is a design choice.
- `RepliesFit` imposes this bound, via `WithinBudget`, on the total for one run each of the sampler, the committer and the prover (one commitment and one request, not a batch)
- in `bindingErrorInQueries` it accounts for one run of the committer
- Statements of Ladder.lean that are not among the six theorems require it of `commit` and of `D`'s own parser, for files in scope
- Each query counts as one, regardless of its length; a typed query of the compiler counts as one query for each digest of its answer
=== VerifierAndGoals.queryBudget
@ def queryBudget
2^64 hash queries. Beyond this number the zero-knowledge theorems give no bound. The statements of Ladder.lean with a constant upper bound on their error, which are not among the six theorems, say nothing about an adversary that makes more queries.
=== VerifierAndGoals.errorFactorPerQuery
@ def errorFactorPerQuery

=== VerifierAndGoals.verifierQueryAllowance
@ def verifierQueryAllowance
The number that `soundnessErrorInQueries` adds to the adversary's and the parser's queries to account for the verifier's own queries. `VerifierWithin` (Ladder/Bits.lean:128, no card on this page) says what is counted and in which unit. The number is a choice; no statement other than `VerifierWithin` says that it is enough. The error of the theorem `sound` contains it, and `sound` has no hypothesis about it. In `bindingErrorInQueries`, where no verifier runs, it is slack.
=== VerifierAndGoals.soundnessErrorInQueries
@ def soundnessErrorInQueries
The soundness error, where t bounds the adversary's queries and n the parser's: with T = t + n + `verifierQueryAllowance` it is `errorFactorPerQuery` · T / 2^128 + (T + 2)² / 2^256. That is 16 / 2^128, or 124 bits, for each query, and about 2^-101 at t = n = 0.
